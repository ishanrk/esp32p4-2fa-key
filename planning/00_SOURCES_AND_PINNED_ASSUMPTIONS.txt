PINNED PROTOCOL FACTS

FIDO HID report usage page is 0xF1D0
application usage is 0x01
input usage is 0x20
output usage is 0x21
reports are 64 bytes
no report ID

Initial CTAPHID packet holds 57 payload bytes
continuation packet holds 59 payload bytes
channel IDs and payload lengths use big endian byte order

Required transport commands for this project

INIT
PING
CBOR
CANCEL
KEEPALIVE
ERROR

Do not implement CTAPHID MSG

CTAP CBOR request payload starts with one command byte followed by CBOR
CTAP CBOR response payload starts with one status byte followed by CBOR on success

Minimal CTAP command values

make credential 0x01
get assertion 0x02
get info 0x04

ES256 COSE algorithm is minus 7
EC2 COSE key type is 2
P 256 curve value is 1

Authenticator data starts with

32 byte SHA 256 relying party ID hash
1 byte flags
4 byte big endian signature counter

MakeCredential with user presence and attested credential data uses flags 0x41
GetAssertion with user presence uses flags 0x01

The v0.1 counter remains zero

When no documented pair exists use a clearly marked local lab pair such as the TinyUSB example VID 0xCAFE with a project specific PID
State that this pair is not suitable for shipping a product
Keep it in one config file

RESEARCH DISCIPLINE

When an implementation behavior differs from the specification

capture the raw HID frames
capture the decoded CTAP request
record the host library version
record the OS browser and site
compare the behavior with the normative protocol section
add a regression test
then change code

Do not patch around a browser symptom before determining whether the fault lives in

USB descriptor
HID report transfer
CTAPHID framing
CBOR representation
CTAP semantics
authenticator data
COSE key encoding
ECDSA signature format
website policy
host permissions
