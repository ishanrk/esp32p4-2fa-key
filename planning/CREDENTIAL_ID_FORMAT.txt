P4KEY CREDENTIAL ID FORMAT VERSION 1

PURPOSE

A WebAuthn relying party stores a credential ID
The browser returns that ID in allowList during authentication

P4Key uses the credential ID as an authenticated encrypted envelope
This avoids a per site credential database on the board

The envelope remains opaque to the browser and relying party

BYTE ORDER

All multi byte protocol fields outside CBOR use network byte order unless a field below is a raw byte array

EXTERNAL FORMAT

total length 100 bytes

byte 0 through 3

ASCII P4K1

hex

50 34 4b 31

byte 4

format version

01

byte 5

internal algorithm

01 means ES256

This internal value is not the signed CBOR value minus 7

byte 6 through 7

reserved

00 00

byte 8 through 19

AES GCM nonce

12 fresh random bytes

byte 20 through 83

ciphertext

64 bytes

byte 84 through 99

AES GCM authentication tag

16 bytes

PLAINTEXT FORMAT

64 bytes before encryption

byte 0 through 31

SHA 256 of the relying party ID string exactly as supplied by CTAP after normal protocol validation

byte 32 through 63

P 256 private scalar

32 byte big endian integer

VALID PRIVATE SCALAR

The scalar must satisfy

one or greater
strictly less than the P 256 group order

Do not reduce an invalid 32 byte value modulo the order during open
Reject it

ADDITIONAL AUTHENTICATED DATA

24 bytes

the external header bytes 0 through 7
then the fixed 16 byte P4Key AAGUID

The nonce is not repeated in AAD because GCM already receives it as the nonce input
The ciphertext and tag authenticate the plaintext
The header and AAGUID bind version algorithm and device model identity

WRAPPING KEY

AES 256

development mode

a 32 byte random root created once and stored in NVS

HMAC root mode

HMAC SHA 256 output under a hardware inaccessible eFuse root

input bytes

ASCII p4key wrap key v1
one zero separator byte
16 byte AAGUID
one byte credential format version

The exact ASCII bytes and separator must be source controlled as a test vector
Do not use strlen on a string whose terminator inclusion is ambiguous
Store the context in an explicit byte array and explicit length

SEAL PROCESS

1 fill a local 64 byte plaintext buffer
2 copy the rpIdHash
3 copy the validated private scalar
4 generate a fresh 12 byte nonce
5 write the fixed eight byte header
6 call AES 256 GCM seal
7 write ciphertext and 16 byte tag
8 zero plaintext
9 return exactly 100 bytes

If any step fails

zero plaintext
zero temporary key material where owned by this function
clear the output length
return a narrow internal error

OPEN PROCESS

1 require input length exactly 100
2 check magic
3 check version
4 check internal algorithm
5 check reserved bytes
6 call AES 256 GCM open with header plus AAGUID as AAD
7 treat any tag failure as an invalid credential
8 compare the decrypted rpIdHash to the requested rpIdHash
9 parse and validate the scalar against the P 256 group order
10 copy scalar only to the caller owned fixed buffer
11 zero plaintext
12 return success

PUBLIC ERROR BEHAVIOR

Do not reveal whether failure came from

magic
version
tag
wrong relying party
invalid scalar

GetAssertion should treat all of these as a nonmatching credential and continue through allowList within the configured maximum

Internal tests may preserve a detailed reason enum
Normal logs may name the class only when debug mode is enabled
Normal logs never print bytes from the credential ID after the fixed header

NONCE RULE

A repeated nonce under one AES GCM key is a severe failure

Use the ESP hardware random source
Generate a new nonce for every credential
Do not derive the nonce from a counter stored in unsafe NVS
Do not reuse the credential key bytes as nonce input

The target test should generate a practical sample such as 4096 nonces and fail on a duplicate
This is a smoke test not a proof

FORMAT CHANGE RULE

Any change to

length
header
plaintext
AAD
key derivation
nonce length
tag length

requires

a new format version
new test vectors
a DECISIONS.txt entry
a compatibility decision
an update to GetInfo max credential ID length if needed

Never reinterpret an old version under new rules
