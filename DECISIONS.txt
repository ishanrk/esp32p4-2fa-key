stage
03 USB FIDO HID enumeration

problem
the TinyUSB task must hand complete reports to one application consumer without heap allocation blocking overwrite or a stale response after physical reconnect

choice
use a statically allocated depth eight ring with a generation in every slot reject the newest report on full and require usb_send to match the generation remembered by the last successful usb_take

alternatives rejected

blocking in the TinyUSB task would delay endpoint service

problem
CTAPHID needs at least four allocated channels a bounded completed message handoff and strict transaction atomicity without per message allocation or overwriting an unread request

stage
04 CTAPHID transport

problem
CTAP 2.2 clearly defines same CID INIT resynchronization and different channel busy behavior but does not explicitly resolve a broadcast INIT allocation while another CID is processing

choice
allow a valid broadcast INIT to allocate and respond without changing the active transaction while an INIT on another already allocated CID still receives channel busy

reason
allocation uses a separate fixed control response and does not inspect replace or unlock the active request so it preserves atomicity while keeping channel discovery responsive during a later user wait

alternatives rejected
aborting the active channel would violate transaction ownership
returning busy for every broadcast INIT would prevent a new client from obtaining a channel during a long user presence wait
allocating from an existing allocated CID would violate the defined retained CID resynchronization behavior

files affected
components/p4_ctaphid/p4_ctaphid_rx.c
tests/host/ctaphid_rx_test.c
docs/CTAPHID_NOTES.txt

reconsider when
a newer pinned CTAP binding defines broadcast INIT arbitration differently or interoperability evidence requires the conservative busy reading
