ENTROPY EVIDENCE

The ESP32-P4 v1.3 bootloader enables the SAR ADC entropy source and disables it
before entering the application. Without RF or that source ESP-IDF documents
esp_random output as pseudo random only. crypto_init therefore re-enables the
supported source with bootloader_random_enable before PSA initialization and
keeps it enabled. The installed bootloader_random.h explicitly permits this
from application code when the RF subsystem is not initialized. P4Key does not
use Wi-Fi Bluetooth or the ADC in this profile.

FALLBACK POLICY

CONFIG_MBEDTLS_AES_SOFT_FALLBACK is disabled.
CONFIG_MBEDTLS_ECC_OTHER_CURVES_SOFT_FALLBACK is disabled.
CONFIG_MBEDTLS_GCM_SUPPORT_NON_AES_CIPHER is disabled.
CONFIG_MBEDTLS_AES_ONLY_128_BIT_KEY_LENGTH is disabled so AES-256 remains valid.

The project uses only P-256 and AES-GCM. Hardware SHA is selected through the
ESP-IDF PSA SHA driver. The SHA source name block_mode_fallback means hardware
block mode when DMA cannot reach a buffer; it does not mean software SHA.

SECURITY BOUNDARY

No eFuse is read written provisioned or modified by this stage. Secure Boot and
Flash Encryption stay disabled. Per-credential private scalars remain visible
to software long enough to export wrap and sign, and temporary copies must be
cleared. This is not a claim of hardware-protected credential keys.
