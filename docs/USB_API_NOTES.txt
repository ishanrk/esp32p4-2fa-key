INITIALIZATION

tinyusb_driver_install accepts a tinyusb_config_t and starts the TinyUSB device
task. TINYUSB_CONFIG_FULL_SPEED(event_cb, event_arg) selects the ESP32 P4
OTG1.1 controller. It does not change which of the two full speed PHYs is wired
to that controller. Descriptor pointers are installed through the descriptor
member and must remain valid for the stack lifetime.

Do not use TINYUSB_DEFAULT_CONFIG for this board connector. On ESP32 P4 that
macro selects TINYUSB_PORT_HIGH_SPEED_0. The required Type-C connector labeled
USB is USB1P1 full speed PHY0 on GPIO24 and GPIO25. PHY0 defaults to USB Serial
JTAG while OTG1.1 defaults to PHY1 on GPIO26 and GPIO27. Before installing
TinyUSB the board helper sets 40 mA drive on GPIO24 and GPIO25 and uses the
installed ESP-IDF usb_wrap_ll_phy_select selector to route USB WRAP to PHY0.
This is a resettable software mux and does not write EFUSE_USB_PHY_SEL.

DESCRIPTORS

The application supplies a device descriptor a full speed configuration
descriptor and string pointers. It leaves the high speed configuration and
device qualifier absent because this connector uses the full speed controller.
The component descriptor layer owns the standard device configuration and
string descriptor callbacks.

The application provides

tud_hid_descriptor_report_cb
tud_hid_get_report_cb
tud_hid_set_report_cb
tud_hid_report_complete_cb when completion signaling is needed
tud_hid_report_failed_cb when transfer failure signaling is needed

tud_hid_set_report_cb receives both control SET_REPORT output and interrupt OUT
data. For interrupt OUT TinyUSB supplies report ID zero and report type output.
tud_hid_n_ready and tud_hid_n_report send one report on the selected interface.

The esp_tinyusb component owns tud_mount_cb and tud_umount_cb. Its
tinyusb_event_cb_t reports TINYUSB_EVENT_ATTACHED and TINYUSB_EVENT_DETACHED to
the application. Optional suspend and resume events require their matching
component configuration symbols.

ENDPOINTS

The application descriptor selects endpoint 0x01 OUT and endpoint 0x81 IN.
Both are interrupt endpoints with 64 byte maximum packets. The installed
TUD_HID_INOUT_DESCRIPTOR template emits the HID interface HID descriptor and
both endpoint descriptors. TinyUSB opens and owns the endpoints from those
bytes; project callbacks only receive or submit complete reports.

The CTAP 2.2 reference descriptor uses interval value 5 for full speed which is
one poll every 5 milliseconds. The descriptor may choose endpoint numbers and
intervals differently but this project keeps the reference values.

PHY AND SPEED

The Type-C connector labeled USB is the direct USB1P1 full speed PHY0 route.
The board helper swaps OTG1.1 onto that PHY before TinyUSB starts and moves USB
Serial JTAG to the unused PHY1 path. CONFIG_USJ_ENABLE_USB_SERIAL_JTAG remains
enabled because the installed pre v3 clock setup supplies PHY0's 48 MHz clock;
the system console remains the separate CH343 UART. The Type-A jumper bank is
the board high speed OTG path and is not selected. The active device limit for
this stage is therefore USB full speed at 12 Mbit/s. Live 303a 4004 enumeration
after the PHY0 mux repair proves the device uses this FS-only controller route.
Installed Windows HID and PnP tools do not expose a separate negotiated speed
field so that field remains explicitly unavailable instead of guessed.

TASK OWNERSHIP

esp_tinyusb creates the TinyUSB service task. The installed default task uses a
4096 byte stack priority 5 and CPU1 on this two core build. USB callbacks execute
from that task and must only do bounded nonblocking work.

P4Key copies a valid 64 byte OUT report into a static depth eight ring and
signals a static binary semaphore before returning. The ring occupies 544
bytes including an unmount generation on every slot. Eight slots absorb a
short host burst while keeping memory fixed. When full it rejects the newest
report and preserves every unread report.

A separate normal application task owns diagnostic bringup and later CTAPHID
processing. One static mutex serializes transmitters. Sending may wait only
from a normal task with one finite overall timeout. Completion disconnect and
resume callbacks wake that path without logging packet bytes.

Every accepted receive report carries the current unmount generation. A
successful take remembers that generation and usb_send rejects a reply after
disconnect. Detach increments the generation clears the ring marks USB not
ready and wakes blocked tasks. Attach also starts with an empty ring. This
dual powered board has no valid routed GPIO for a native connector VBUS
monitor, so suspend conservatively advances the same connectivity generation
and drops queued or held work. Resume restores readiness only when the stack
still reports the device configured.

The pre v3 PHY0 clock depends on CONFIG_USJ_ENABLE_USB_SERIAL_JTAG remaining
enabled even though the system console stays on UART. sdkconfig defaults and a
compile guard pin that invariant. If TinyUSB installation fails after the mux
swap the Type-C connector may not expose USB Serial JTAG again until hardware
reset; PWR USB TO UART remains the recovery and logging path.

KNOWN LIMITS

This stage proves USB HID shape and a private opt in diagnostic exchange only.
It does not implement CTAPHID or claim FIDO behavior. USB disconnect detection
depends on the host and controller event path and must be checked on the real
connector. A target unplug test must record whether the stack reports detach or
suspend while separate UART power remains connected. No CDC interface is
enabled and no serial number derives from chip identity eFuse or MAC data.
