P4KEY USB TEST

SCOPE

Prompt 03 exposes one FIDO shaped HID interface and one opt in fixed diagnostic
exchange. It does not implement CTAPHID CTAP CBOR credentials or a general
echo protocol.

The native device cable connects the Type-C connector labeled USB to the host.
Keep PWR USB TO UART connected separately for COM7 flashing and logs. Use a
known data-capable cable and do not add another 5 V source.

HOST REQUIREMENT

The only Prompt 03 Python dependency is pinned in requirements-host.txt.

Linux setup from the repository root

python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-host.txt

Source checks do not import hidapi and run before that package is installed.
The live discovery descriptor and probe modes import it only when requested.

SOURCE CHECKS

python3 scripts/usb_desc_check.py
python3 -m unittest discover -s tests/host -v

The source checker reads the real C descriptor arrays and Kconfig defaults. It
requires configuration one interface zero alternate zero class 3 subclass 0
protocol 0 HID 1.11 two strict interrupt endpoints 64 byte input and output
reports inside usage page F1D0 usage 01 with no report ID and no other USB
class. It also retains the finite deadline and suspend resume regressions.

WSL FIRST

Check WSL before using a Windows fallback.

lsusb -d 303a:4004
python3 scripts/usb_find.py --vid 0x303a --pid 0x4004
python3 scripts/usb_desc_check.py --live-hid --vid 0x303a --pid 0x4004

For a Linux standard descriptor capture use a filtered command only.

lsusb -v -d 303a:4004 > captures/usb-lsusb.txt
python3 scripts/usb_desc_check.py --lsusb captures/usb-lsusb.txt --vid 0x303a --pid 0x4004

The parser records expected and observed descriptor facts. A field unavailable
from the selected host path is printed as UNAVAILABLE and is never guessed.
The captures directory is ignored because later captures may contain account
data.

WINDOWS FALLBACK

If WSL again shows only its root hubs use Windows directly. Do not spend time
installing a WSL USB bridge merely for this stage. Windows currently exposes
the separate CH343 log connection as COM7.

Run these setup commands in Windows PowerShell. They do not require a driver
replacement because the device remains HID class.

$repo = "\\wsl.localhost\Ubuntu\home\ishan\esp32p4-2fa-key"
$venv = "$env:TEMP\p4key-hidapi-0.15.0"
py -3 -m venv $venv
& "$venv\Scripts\python.exe" -m pip install -r "$repo\requirements-host.txt"

Then run

& "$venv\Scripts\python.exe" "$repo\scripts\usb_find.py" --vid 0x303a --pid 0x4004
& "$venv\Scripts\python.exe" "$repo\scripts\usb_desc_check.py" --live-hid --vid 0x303a --pid 0x4004

Windows HIDAPI reconstructs a logically equivalent report descriptor because
the Windows HID API does not expose the original raw bytes. The checker labels
that result and compares its FIDO usages report sizes and lack of report ID
semantically. The exact 34 source bytes remain a separate mandatory check.

USB FIND

usb_find calls hidapi enumerate with the requested VID and PID and filters the
returned records again. It rejects an exposed mismatching interface or usage
before opening a candidate. It prints path interface usage page usage and
descriptor-derived input and output lengths when the host exposes them. If more
than one FIDO-shaped candidate is present use the printed path with the other
live tools. The probe validates the opened report descriptor before it writes.

BRINGUP PROBE

The diagnostic firmware must have been built with
CONFIG_P4KEY_USB_BRINGUP=y. The probe has no default mode.

python3 scripts/hid_probe.py --bringup --vid 0x303a --pid 0x4004 --timeout-ms 2000

For Windows PowerShell

& "$venv\Scripts\python.exe" "$repo\scripts\hid_probe.py" --bringup --vid 0x303a --pid 0x4004 --timeout-ms 2000

The probe sends the one fixed nonsecret 64 byte request. HIDAPI needs a leading
host-only zero report ID byte so its write buffer is 65 bytes while the USB OUT
report remains exactly 64 bytes. It requests exactly 64 response bytes with a
finite timeout checks the fixed response and closes the handle on every exit.
It never prints either report.

After flashing the normal build verify that the private exchange is absent.

python3 scripts/hid_probe.py --normal-no-response --vid 0x303a --pid 0x4004 --timeout-ms 2000

This explicit negative mode passes only when no response arrives before the
finite deadline. It fails if normal firmware answers the private pattern.

LINUX HIDRAW ACCESS

A local administrator may choose a development rule like the following when a
normal Linux host lists the device but hidapi cannot open its hidraw path.

SUBSYSTEM=="hidraw", ATTRS{idVendor}=="303a", ATTRS{idProduct}=="4004", TAG+="uaccess", MODE="0660", GROUP="plugdev"

Review the group name and local access policy before installing a rule. Neither
the project scripts nor Codex installs a rule reloads udev or invokes sudo.
Unplug and reconnect the native USB cable after an administrator activates a
new rule according to the host policy.

OBSERVED DESCRIPTOR RECORD

Commit a sanitized checker result to docs/USB_DESCRIPTOR_SAMPLE.txt after the
target enumerates. Record OS Python hidapi and lsusb versions where available.
Keep only whitelisted VID PID class interface endpoint usage report length and
PASS or UNAVAILABLE facts. Do not store report payloads a serial string an
unstable HID path or unrelated USB devices.

UNPLUG REPLUG GATE

Keep PWR USB TO UART connected for COM7 logs. Unplug only the data cable from
the Type-C connector labeled USB. Wait until the host device disappears.
Reconnect the same known data-capable cable to USB without pressing BOOT or
RST and without removing PWR. After reconnect Codex will verify that the same
VID PID returns, run the fixed probe, and capture whether the diagnostic
counters recorded unmount or suspend plus mount or resume.

This is a manual physical test. Record that exact action in PROJECT_STATE.txt
and stop for the user when the action is required rather than simulating it
with a reboot.
